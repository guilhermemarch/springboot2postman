# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.0.0] - 2026-08-13

Full rewrite of the parser and output pipeline around one principle:
**never invent, always report**. Everything in the output traces back to the
source code or the spec; anything unresolved is reported instead of guessed.

### Fixed (parser correctness)

- `@RequestMapping(value = "...")` and all named annotation attributes are
  now parsed structurally from the CST. In v1 they were silently dropped:
  the base path disappeared and `method = RequestMethod.POST` exploded into
  5 endpoints
- `ResponseEntity<List<T>>` no longer produces a nested array-of-arrays;
  wrappers unwrap before collection matching
- Records, interfaces and enums are parsed (v1 generated zero endpoints for
  API-first projects and empty schemas for record DTOs)
- Multi-module Maven/Gradle projects work (v1 found no controllers)
- `src/test` sources are never scanned; `@RestControllerAdvice` is no longer
  mistaken for a controller
- Controller inheritance resolves, including generic base controllers
  (`CrudController<T, ID>`) with type-parameter substitution
- DTO scanning is CST-based and import-aware: inheritance, nested generics
  (`Map<String, List<String>>`), Jackson (`@JsonProperty`, `@JsonIgnore`),
  Bean Validation constraints, cross-package name collisions
- Constants in mapping paths resolve (same file, cross-file and
  concatenations); `MediaType.*_VALUE` constants resolve in
  `produces`/`consumes`
- Multi-document `application.yml` parses (v1 fell back silently to
  localhost:8080); relaxed binding (`contextPath`) and
  `spring.webflux.base-path` supported
- `--project <url>` works again (v1 destroyed URLs with `path.resolve`)
- `faker.internet.username()` crash that silently discarded whole
  controllers
- Postman output: path variables use Postman's native representation
  (v1 emitted `{{userId}}` variables that were never declared — every
  collection with path variables was broken on import); no more duplicate
  request names or double spaces; 204 responses have no body; `$ref`s never
  contain generics; operationIds are unique; duplicate path+method mappings
  are reported instead of silently overwritten
- `--seed` is actually deterministic now (byte-identical output),
  independent of parsing concurrency

### Added

- `@RequestPart`/`MultipartFile` → `multipart/form-data` bodies
- `@ModelAttribute` and unannotated POJOs expand into query parameters;
  unannotated simple types bind as optional query params (Spring semantics)
- `@CookieValue`, `@ResponseStatus`, `produces`/`consumes` content types,
  `@Deprecated`, Javadoc → endpoint/parameter descriptions
- Success/error statuses detected from `ResponseEntity` factory calls in
  method bodies (source-derived, not guessed)
- Resolution report after every run (endpoints, schemas, skipped files,
  unresolved types) and `--strict` to fail CI on any unresolved item
- `diff` command: compare generated API against an existing collection or
  spec; exit 1 on drift (`--fail-on breaking|any`)
- `.http` output format (IntelliJ HTTP Client / VS Code REST Client)
- `--strategy auto|parser|openapi` (v1 silently preferred a stale committed
  spec over the code) plus a loud warning in auto mode
- `--header`/`--bearer` for OpenAPI URLs behind auth; real error causes
  surfaced (HTTP status, ECONNREFUSED, HTML login pages)
- `--quiet`, `--out -` (stdout), config file
  (`springboot2postman.config.json`)
- Postman auth derived from the spec's `securitySchemes` (bearer, basic,
  apiKey) — only when declared
- Environment file mirrors all collection variables
- Realistic multi-module test corpus (`tests/fixtures/shop-api`) with a
  regression test for every v1 audit finding; output invariants enforced
  in CI

### Removed (breaking)

- All data fabrication: invented DTO fields for unknown types, fake 400/404
  saved responses with hardcoded Spring Boot 2 error bodies, English-only
  entity-name heuristics, `Authorization: Bearer` header stamped on every
  request, forced `Accept`/`Content-Type` headers, "Generated by
  SpringBoot2Postman" as the collection description
- The `springboot-postman-gen` duplicate bin name
- Node 16 support (`engines` now `>=18`)

## [1.3.0] - 2026-06-06

### Added

- `validate` CLI subcommand for CI checks
- `--dry-run` flag to analyze projects without writing files
- `--env-out` to generate a Postman environment file
- Snapshot and CLI integration tests
- Coverage reporting in CI

### Fixed

- `@RequestMapping` without explicit `method` now expands to GET, POST, PUT, PATCH, DELETE
- `getDto()` prefers exact and suffix matches instead of fragile prefix matching
- `extractEntityName()` handles nested generics more reliably

### Changed

- CLI uses subcommands (`generate` default, `validate`)
- Strategy `validate()` logs failures when `--verbose` is enabled

### Removed

- Dead code: `producesJson`, `consumesJson`, `TypeResolver.generateExample`
- Legacy fixture at `tests/controller/UserController.java`

## [1.2.0] - 2026-06-06

### Added

- CST-based Java parsing via `java-parser` (replaces regex parser)
- `--format openapi` output for intermediate OpenAPI spec
- `--seed` for deterministic mock data generation
- `--no-enhance` flag to skip Postman collection enhancements
- OpenAPI file path support for `--project`
- Expanded OpenAPI discovery in `src/main/resources/`, `docs/`, etc.
- `application.properties` / `application.yml` reading for context path, port, and app name
- `Pageable` parameter support (page, size, sort query params)
- PostmanEnhancer applied to OpenAPI strategy path as well
- Test suite with fixtures, unit tests, and integration tests
- CI workflow, ESLint, Prettier, LICENSE, and `.gitignore`

### Fixed

- OpenAPI `$ref` schemas now populated from DTO scanner
- Controller scanner glob fallback when `*Controller.java` helpers exist
- Path variable double-templating in PostmanEnhancer
- CLI options no longer leak into `openapi-to-postmanv2` converter

### Changed

- Collection title uses `spring.application.name` when available
- Base URL defaults from project config when `--base-url` is omitted

## [1.1.0] - 2026-01-13

### Added

- **MockDataGenerator** - Realistic fake data using @faker-js/faker with field-name-aware generation
- **DtoScanner** - Automatic DTO class discovery and field extraction
- **PostmanEnhancer** - Post-processing for production-ready collections
- **Path variables as Postman variables** - Converts `{id}` to `{{userId}}` format
- **Collection-level variables** - `baseUrl`, `token` added by default
- **Multiple response examples** - 200, 201, 204, 400, 404 per endpoint type
- **Standard error responses** - Includes timestamp, status, error, message, path
- **Default headers** - Accept, Content-Type, Authorization (Bearer {{token}})
- **Improved request naming** - Clean names without HTTP method prefix

### Changed

- Request body examples now contain realistic mock data based on field names
- Response examples include realistic data (names, emails, dates)

## [1.0.0] - 2026-01-08

### Added

- Initial release
- Dual strategy support: OpenAPI and Parser strategies
- Static analysis of Spring Boot controllers (no compilation required)
- Support for `@RestController`, `@Controller`, `@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`, `@PatchMapping`
- Parameter extraction: `@PathVariable`, `@RequestParam`, `@RequestBody`, `@RequestHeader`
- Java to JSON Schema type conversion
- `--include` and `--exclude` glob patterns for package filtering
- `--concurrency` option for parallel controller parsing
- Progress reporting during large codebase processing
- Comprehensive error handling with error codes
